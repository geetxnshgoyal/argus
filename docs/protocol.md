# Argus attendance protocol (Phase 1)

> **Status: draft (M0).** Derived from [spec §5–§7](spec/phase1-build-spec.md)
> as amended by ADR-0004 through ADR-0011. Implemented in M3 (device binding)
> and M4 (attendance core). Keep this file in sync with the code: any change to
> a byte layout, window or check order must update this document and its
> test vectors in the same commit.

## 1. Principles

- **Server time is authoritative.** Clients measure an offset with `GET /v1/time`; epochs are always computed from server time.
- **The server decides.** The app reports signals; role, enrollment, time, location and the final decision are server-side.
- **Signatures cover exact bytes.** The server verifies over the bytes it received and never re-serializes to verify (ADR-0011).
- **Least key exposure.** K_s never leaves the server. The display holds only a key for the current round (ADR-0004).

## 2. Notation and encodings

| Symbol | Meaning |
|---|---|
| `‖` | byte concatenation |
| `u32be(n)`, `u64be(n)` | unsigned big-endian integer, 4 / 8 bytes |
| `uuid16(x)` | the 16 raw bytes of a UUID (RFC 9562 byte order) |
| `b64url(x)` | base64url without padding |
| `HKDF(ikm, salt, info)` | HKDF-SHA256 (RFC 5869), 32-byte output |
| `HMAC(k, m)` | HMAC-SHA256 |
| `SHA256(x)` | SHA-256 digest |
| ASCII labels | e.g. `"argus/v1/qr"`, encoded as UTF-8 bytes, no terminator |

All IDs are UUIDv7, generated by the server. Timestamps in JSON are RFC 3339 UTC; integer times are Unix epoch milliseconds.

## 3. Keys

| Key | Where it lives | Purpose |
|---|---|---|
| Master key (32 bytes) | server settings (`ARGUS_MASTER_KEY`), never in the DB | encrypts K_s at rest (AES-256-GCM) |
| K_s (32 random bytes, per attendance session) | DB (encrypted), server memory (decrypted, in-process cache) | root of all session tokens |
| `K_qr,r = HKDF(K_s, uuid16(session_id), "argus/v1/qr" ‖ u32be(r))` | server; the paired display, for round `r` only | QR tags for round `r` |
| `K_ble = HKDF(K_s, uuid16(session_id), "argus/v1/ble")` | server only (Phase 2) | BLE tokens, same epochs |
| Device session key (P-256) | student phone hardware keystore, non-exportable | signs refresh + routine requests (ADR-0008) |
| Device attempt key (P-256) | student phone hardware keystore, non-exportable, requires user auth | signs attempts, support requests, rebind confirmations |

K_s ciphertext format: `nonce (12 bytes) ‖ ciphertext (32 bytes) ‖ tag (16 bytes)`, AES-256-GCM with associated data `"argus/v1/ks" ‖ uuid16(session_id)`, so a ciphertext cannot be moved to another session.

## 4. Device binding (M3)

1. Student signs in with college SSO (OIDC auth code + PKCE).
2. App calls `POST /v1/devices/bind/challenge` → `{challenge}` (32 random bytes, single use, 5 min).
3. Native module generates the **session key** and the **attempt key** (Android: Keystore, StrongBox if available, attestation challenge = `challenge`; iOS: Secure Enclave).
4. App sends `POST /v1/devices/bind` with a JCS payload `{v, challenge, session_pub, attempt_pub, platform, model, os_version, app_version, android_id?}` plus:
   - Android: Play Integrity standard token (`requestHash = b64url(SHA256(payload))`) and the key-attestation certificate chains for both keys;
   - iOS: App Attest attestation object (`clientDataHash = SHA256(payload)`); the server sets a DeviceCheck bit.
5. Server verifies: challenge fresh and unused; attestation chains to the platform root; key attestation shows hardware-backed keys, verified boot, our package and signing certificate, and that the attempt key requires user authentication; Play Integrity / App Attest verdicts.
6. Same-device check: Android keyed `HMAC(server_secret, android_id)`, iOS DeviceCheck bit (ADR-0009).
7. First device → active. Replacement device → rebind request, eligible after 48 h or Acad Ops approval; the old device stays active until then and can cancel (ADR-0007).

## 5. Attendance session (M4)

### 5.1 Start

`POST /v1/teacher/class-sessions/{id}/attendance/start` (teacher web session).

Server checks: caller is the class session's teacher; `now ∈ [start − 10 min, end]`; class session `scheduled`; no active attendance session for it (partial unique index).

Server creates the attendance session and round 1 (`mode=full`), sets `t0 = now` (ms), generates K_s, stores its ciphertext, and caches the decrypted K_s in process memory.

### 5.2 Display pairing (ADR-0004)

1. Classroom PC opens `/display`. The page generates `pair_secret` (32 random bytes) in memory and calls `POST /v1/display/pairings` with `SHA256(pair_secret)` → `{pairing_id, code}` (short code, 5 min, single use). It shows `code` as text and as a QR. It never shows `pair_secret`.
2. The teacher, in their authenticated web session, enters or scans `code` and picks the attendance session. The server links the pairing to the session.
3. The display polls `POST /v1/display/pairings/{pairing_id}/claim` with `pair_secret` until linked, then receives `{session_id, round, t0, epoch_ms: 3000, k_qr: b64url(K_qr,round), server_time}`.
4. On each new round, the display fetches the new `k_qr` with its `pair_secret`. On session end it is told to wipe keys; it also wipes them when its own clock passes the class end time.
5. If the teacher runs the web app on the projected machine itself, the app opens the display directly using the teacher's session (no code).

Display rules (spec §6): WebCrypto HMAC; full-screen, high-contrast QR; Screen Wake Lock; keys only in memory (never `localStorage`); round number and countdown shown; no student data.

### 5.3 QR generation

```
epoch = floor((server_now_ms − t0) / 3000)
tag   = first12bytes( HMAC(K_qr,r, "argus/v1/qr-tag" ‖ uuid16(session_id) ‖ u32be(r) ‖ u64be(epoch)) )
QR    = "argus://a/" + session_id + "/" + r + "/" + epoch + "/" + b64url(tag)
```

`session_id` is the lowercase canonical UUID string; `r` and `epoch` are decimal. The app accepts QR content **only from its own camera**; `argus://` is not a deep link for attendance (ADR-0011).

### 5.4 Attempt (student app)

1. On opening Scan: start a fresh precise location fix (reject fixes older than 30 s; prompt for precise if only approximate is granted); warm up Play Integrity; if the attempt key's auth window has expired, prompt for unlock/biometric **before** scanning.
2. Keep decoding frames; when the location fix and key are ready, take the **most recent** decoded QR and submit immediately. This minimizes QR age and helps legitimate students meet the grace window.
3. Payload (JCS canonical JSON bytes):

```json
{
  "v": 1,
  "session_id": "…",
  "round": 1,
  "epoch": 1234,
  "tag": "…",
  "device_id": "…",
  "nonce": "<b64url 16 random bytes>",
  "device_time": "2026-09-23T09:02:11.123Z",
  "location": {"lat": 0, "lon": 0, "accuracy_m": 0, "fix_age_ms": 0, "is_mock": false},
  "signals": {},
  "app_version": "x.y.z",
  "offline_queued": false
}
```

4. `signature = ECDSA-P256-SHA256(attempt_key, payload_bytes)`, DER.
5. Attestation: Android Play Integrity standard token with `requestHash = b64url(SHA256(payload_bytes))`; iOS App Attest assertion with `clientDataHash = SHA256(payload_bytes)`.
6. `POST /v1/attendance/attempts` with body `{payload: b64url(payload_bytes), signature: b64url(sig), attestation: {…}}`.

### 5.5 Server validation (ADR-0005 order; fail fast with reason code)

| # | Check | Reject code |
|---|---|---|
| 1 | Device exists, bound to the authenticated student, not revoked, past `eligible_at` | `device_not_active` |
| 2 | Signature valid over the exact payload bytes (attempt key) | `bad_signature` |
| 3 | Nonce unused: `INSERT INTO used_nonces (device_id, nonce, expires_at) … ON CONFLICT DO NOTHING` affects 1 row | `replayed_nonce` |
| 4 | Session open; round open; student enrolled (and in the lab group if group-specific); in targeted rounds, student is targeted | `session_closed`, `round_closed`, `not_enrolled`, `not_targeted` |
| 5 | Epoch window (below) and constant-time tag comparison | `epoch_expired`, `bad_tag` |
| 6 | No accepted attempt for (round, student) (DB partial unique index) | `already_marked` |
| 7 | Attestation valid and bound to `SHA256(payload_bytes)`; provider outage → flag `attestation_unavailable`, **not** rejection | `attestation_failed` |
| 8 | Location: reject only if `distance_to_geofence − accuracy_m > 0` AND `accuracy_m ≤ 100` AND `!is_mock` | `off_campus` |

**Epoch window.** With `E = floor((received_ms − t0)/3000)`: accept `epoch = E`, or `epoch = E − 1` if `received_ms − (t0 + E·3000) ≤ 2000` (sets `late_in_window`). Otherwise `epoch_expired`. `received_ms` is the server clock when the request body was fully read.

Rate limit: 10 attempts per device per minute (Postgres counter; ADR-0003).

### 5.6 Soft signals and decision

Scorers are pluggable (`score(ctx, attempt, observations) → {points, flags}`) with weights and kill switches in `risk_settings` (ADR-0014).

| Signal | Default weight |
|---|---|
| `location_mock` | +70 (ADR-0010) |
| `location_poor_accuracy` (> 100 m) or no fix | +20 |
| `not_campus_network` | +15 |
| `late_in_window` | +10 |
| `device_recently_rebound` (< 7 days) | +15 |
| `attestation_unavailable` | +20 |
| `recent_flag_history` | +10 per flag in 14 days, cap +30 |

Decision: `< 30` verified; `30–69` flagged (present, shown to teacher, spot-check priority); `≥ 70` flagged_high (present pending resolution, shown first). Soft signals never reject.

Stored per attempt: decision, reason codes, score, and minimized signals only: location result (`inside|outside|unknown`), accuracy, distance to geofence rounded to 50 m, `is_mock`. **Raw coordinates are never persisted or logged.**

### 5.7 Rounds

- `full`: every enrolled student scans. `targeted` (default recheck): unmarked + flagged + random sample; others see "You're verified, nothing to do". `end`: optional end-of-class sweep.
- Each round has its own `K_qr,r`, so tags never collide across rounds.
- Outcomes (ADR-0010): missed recheck → `missed_recheck` flag (flagged_high), teacher decides; first acceptance in a round opened > 10 min after class start → `late`.

### 5.8 Spot checks and headcount

Suggestion: all flagged_high + up to 5 flagged (score-weighted) + 3 random verified (weighted by score + 1). Results: `confirmed` | `absent` (record → absent, risk flag) | `no_response` (risk flag, record unchanged until resolved). Headcount: if `present > headcount + 2`, suggest more spot checks.

### 5.9 End

`POST /v1/attendance/sessions/{id}/end`: close the open round; unmarked → absent; notify the display to wipe keys; keep the support window open until class end. K_s ciphertext is kept **10 more minutes** for offline-queued attempts, then zeroed and evicted (ADR-0011).

### 5.10 Offline

- Display: keeps generating QR offline within the current round.
- Student app: may queue a signed attempt for up to 10 minutes (`offline_queued: true`). Server accepts only if the tag was valid for the epoch at `device_time` (±1 epoch) and marks it flagged with `offline_queued`. **Not counted present until the teacher confirms** (ADR-0010). `device_time` is client-controlled, so teacher confirmation is the real control.

## 6. Support requests (M6)

- Only from the bound device (attempt key), only while the class session is ongoing.
- Server snapshots evidence (identity, session, all attempts with reason codes, device + attestation, location result, network result, flags, last 30 days).
- Verifier **Approve** requires evidence score below threshold **and** at least one attempt this session with a valid tag for this session (ADR-0006). Otherwise only **Ask teacher** (push: "Is {name} ({USN}) in the room?" → Yes / No / Call out) or **Reject**.
- After class ends: only `attendance_corrections` (teacher attestation + Acad Ops approval, two different people).

## 7. Test vectors

Added in M4 alongside the implementation: fixed K_s, session_id, round and epoch → expected `K_qr,r` and tag; a fixed payload → expected SHA-256 and a verifiable signature. The web display, the server and (for tag checks in tests) the app must all reproduce them.
