# ADR-0011: Protocol encoding details

**Context.** The spec leaves byte-level encodings open. Ambiguity here causes signature failures across Kotlin, Swift, Dart and TypeScript, or security bugs.

**Decision.**
- **IDs:** UUIDv7 generated by the server (Postgres 16 lacks `uuidv7()`).
- **Signatures over exact bytes.** The client produces the payload as RFC 8785 (JCS) canonical JSON and sends those exact bytes (base64url) with the signature. The server verifies the signature over the received bytes, then parses. It never re-serializes to verify (avoids float-formatting mismatches). Signature: ECDSA P-256 with SHA-256 over the payload bytes, DER-encoded (Android `SHA256withECDSA`, iOS `ecdsaSignatureMessageX962SHA256`); no double hashing.
- **Attestation binding:** Play Integrity `requestHash` = base64url(SHA-256(payload bytes)); App Attest `clientDataHash` = SHA-256(payload bytes).
- **HMAC inputs are fixed-width binary**, never concatenated decimal strings: tag = HMAC-SHA256(K_qr,r, "argus/v1/qr-tag" ‖ session_id (16 bytes) ‖ u32be(round) ‖ u64be(epoch)), first 12 bytes, base64url without padding.
- **QR accepted only from the in-app camera.** The `argus://` scheme is not registered as a deep link for attendance; otherwise a forwarded link would make relaying a single tap.
- **Key retention:** K_s (encrypted) is kept for 10 minutes after the session ends so offline-queued attempts can still be verified, then the ciphertext is zeroed.

**Consequences.** See `docs/protocol.md` for the full byte layouts; test vectors are added with the implementation in M4.
